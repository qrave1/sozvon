# Разработка Sozvon

## Устройство проекта

- Backend: Go 1.27, Pion WebRTC v4, Pion TURN v5. Версию Go в `go.mod` и Dockerfile менять согласованно.
- `main.go`: запуск HTTP, маршруты и отдельная команда `turn`.
- `internal/sfu/`: SFU, сигналинг, комнаты, публикации, подписки, RTP/RTCP и интеграционные тесты.
- Сигналинг групповых звонков использует `coder/websocket`; старый mesh удалён.
- `internal/config/`: конфигурация из окружения. `internal/turnserver/`: TURN-сервер.
- `web/`: обычные HTML/CSS/JavaScript без сборки; единственный клиент в `client.js` и `index.html`.
- Звонки: `/?room=<id>` и `/ws`. Старые `/sfu` и `/sfu.html` перенаправляют на `/` с сохранением query; `/sfu/ws` и `/sfu.js` возвращают 404.
- Единственная архитектура — SFU; выбора media mode и отдельных вариантов интерфейса нет. На фронте и в новых ссылках название архитектуры не отображается.
- Подробная матрица сценариев и текущие ограничения: [docs/sfu-group-call.md](docs/sfu-group-call.md).

## Правила изменений

- Перед правками прочитать затронутый код, тесты и `git status`. Не откатывать чужие изменения.
- Проверять единственный клиент групповых звонков при изменениях маршрутов, конфигурации и UI.
- Предпочитать существующие подходы; не добавлять фронтенд-фреймворк или отдельную сборку без необходимости.
- Изменения протокола согласовывать между `internal/sfu/` и `web/client.js`; учитывать несовпадение версий сервера и закешированного клиента при деплое.
- Форматировать изменённые Go-файлы через `gofmt`; зависимости обновлять Go-инструментами вместе с `go.sum`.
- Не коммитить `.env`, секреты, локальные бинарники и артефакты тестов. Не писать TURN-пароли и полные SDP с сетевыми данными в обычные логи.
- Для исправления медиа-багов добавлять регрессионный тест, проверяющий передачу медиа, а не только сигналинг.

## Инварианты SFU

- У клиента есть выделенные исходящие audio/video senders даже при отсутствии камеры на входе. Не искать локальный sender по первому transceiver нужного типа: он может принадлежать входящему треку.
- Первый offer клиента устанавливает транспорт и каналы публикации. Answer не может добавлять новые media sections сверх offer.
- Сначала отправляется `joined` с answer, затем активируются подписки и сервер делает новый offer. Поздний участник должен получить все существующие публикации комнаты.
- Переговоры сериализованы: одновременно только один неподтверждённый server offer. Изменения подписок во время него остаются pending и применяются после answer.
- Не подписывать участника на себя и не передавать треки между комнатами. При N участниках с аудио и видео каждый получает `2 * (N - 1)` треков.
- Идентичность публикации и stream ID должны сохранять связь с владельцем в roster. При выходе удаляются публикации и подписки; устаревшие снимки комнаты не должны возвращать удалённые треки.
- Не пересылать входящие RTP header extensions MID/RID/transport sequence напрямую: они относятся к входящему транспорту. Исходящий транспорт обслуживают его interceptors.
- Читать RTCP исходящих senders. PLI/FIR подписчика направлять издателю с SSRC исходного трека; downstream retransmission обслуживают стандартные Pion interceptors.
- После подписки и изменения источника видео запрашивать свежий ключевой кадр.
- Не удерживать блокировки комнаты при сетевой записи. Новые goroutines должны иметь понятный путь завершения при закрытии peer/сервера.

## Инварианты клиента

- Смена камеры и текущий screen sharing используют `replaceTrack`, сохраняют sender и не требуют выхода из комнаты. Сейчас экран заменяет камеру, а не публикуется одновременно с ней.
- Настройки битрейта применять через `setParameters` сразу в комнате и повторно после смены источника; асинхронные изменения sender сериализовать.
- Кодеки согласовываются автоматически. Не возвращать ручной выбор кодеков и правки SDP для их принудительного выбора.
- Использовать входящие MediaStreams и учитывать `addtrack`, `removetrack`, `unmute`, `ended`. Не полагаться только на `onended` при удалении трека через SDP.
- Входящее аудио воспроизводится отдельно от видео. Видео muted, чтобы не дублировать звук; отключение камеры не должно выключать аудио.
- Учитывать ограничения autoplay и повторять запуск аудио после пользовательского действия.
- После leave/rejoin игнорировать старые WS-события и результаты асинхронного захвата. Поздно полученные треки останавливать, а не возвращать в покинутую комнату.
- На мобильных устройствах смена физической камеры может требовать освобождения предыдущего устройства; сохранять обработку ошибки и восстановление состояния.

## Запуск и окружение

- Запускать из корня: статические файлы читаются из `./web`. HTTP: `go run .`; TURN отдельно: `go run . turn`.
- Конфигурация читается из process env; приложение само `.env` не загружает. Docker Compose передаёт его через `env_file`.
- HTTP-переменная называется `PORT` (например, `:8000`), не `HTTP_PORT`. Актуальные имена и значения по умолчанию смотреть в `internal/config/config.go` и `.env.example`.
- `SFU_UDP_PORT` (по умолчанию 40000) общий для SFU через UDP mux; не выделять отдельный порт каждому участнику.
- `SFU_PUBLIC_IP` задаёт публичный адрес кандидатов; при пустом значении используется `TURN_RELAY_IP`. Сохранять локальные кандидаты для работы внутри LAN.
- Для продакшена проверять проброс SFU UDP, firewall, TURN listener и relay-доступность. Рабочий HTTP/WS ещё не означает рабочий медиатранспорт.
- Камера/микрофон в браузере требуют secure context: localhost при разработке либо HTTPS при удалённом доступе.
- Не занимать порт уже работающего сервера пользователя. Для ручной проверки выбирать свободные HTTP и SFU UDP порты.

## Проверки

Из корня проекта, для изменений Go и SFU-клиента:

```powershell
go test ./... -count=1
go vet ./...
node --check web/client.js
go build -o .sfu-check.exe .
node --test tools/sfu_group.test.cjs
git diff --check
```

- Browser test требует Node.js, установленный Google Chrome и модуль `playwright`. `PLAYWRIGHT_MODULE_PATH` позволяет указать абсолютный путь к модулю из доступного runtime.
- Тест сам запускает и останавливает сервер: HTTP 18003, UDP 40003. Не запускать несколько таких тестов одновременно с общим UDP-портом.
- `SFU_TEST_HTTP_PORT` меняет HTTP-порт; `SFU_TEST_BINARY` меняет путь к собранному бинарнику (в том числе на Linux).
- Для повторной проверки групповых гонок: `go test ./internal/sfu -run TestGroupEveryParticipant -count=5 -timeout=90s`.
- Для изменений конкурентного Go-кода также запускать `go test -race ./internal/sfu`, если доступны CGO и C-компилятор. Если проверка недоступна, прямо указать это в результате.
- Для документации достаточно сверить команды с кодом и выполнить `git diff --check`; полный медиа-набор не обязателен.
- Не объявлять тесты пройденными, если они не запускались. Отдельно сообщать о недоступных инструментах и непроверенных сценариях.

## Что проверять в групповом звонке

- Не только `joined`/roster/`ontrack`: должны расти `bytesReceived` и `framesDecoded`, аудиоэлемент должен воспроизводить звук.
- Четыре участника, поздний вход, выход и повторный вход, изоляция комнат и отсутствие собственных треков среди входящих.
- Вход без камеры и включение позже; смена камеры без reconnect; камера выключена, но аудио продолжает работать.
- Применение битрейта в комнате; экран и возврат к камере; mute/unmute; завершение захвата после выхода.
- Chromium с fake media и мобильным viewport не проверяет реальные Android/iOS/Safari, переключение аппаратной камеры, OS screen picker или production TURN. Такие проверки выполнять отдельно на устройствах и внешней сети.
- Не описывать как готовые: одновременные камера и экран, simulcast, адаптация качества для каждого подписчика и автоматический ICE restart.
