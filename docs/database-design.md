# SQLite: первый этап

Этот документ фиксирует границы слоя хранения до реализации аккаунтов и HTTP API.

Схема автоматически обновляется при `go run .` и при запуске контейнера.

## Пакеты и запуск

- `internal/database`: открывает и закрывает соединение SQLite через GORM и
  pure-Go драйвер `github.com/glebarez/sqlite` (совместимый с `CGO_ENABLED=0`),
  создаёт каталог для файла БД, настраивает foreign keys, busy timeout и WAL.
- `internal/database/repository`: выполняет запросы к `users` и `refresh_tokens`
  через GORM Generics. Структуры строк с GORM-тегами остаются приватными и
  лежат рядом с соответствующим репозиторием.
  `AutoMigrate` вызывается при запуске HTTP до открытия медиасервера.
- `internal/domain`: общие структуры `User`, `Session` и `Device` без
  зависимостей от GORM или SQLite. Методы репозиториев принимают и возвращают
  эти типы.
  Каждый метод принимает `context.Context`; операции, которые должны быть
  атомарными, выполняются в одной SQL-транзакции.
- Будущий сервис аккаунтов выбирает, когда создавать, обновлять и удалять сессии.
  Репозиторий не выпускает JWT, не хеширует пароли и не работает с HTTP cookies.

Один процесс HTTP использует один файл SQLite. Для in-memory тестов соединение
должно оставаться открытым на всё время работы репозитория.

## Схема

`users`:

| Поле | Ограничение |
| --- | --- |
| `id` | UUID, первичный ключ |
| `login` | Уникальный, сравнение с учётом регистра |
| `display_name` | Обязательное |
| `password_hash` | Обязательное |
| `created_at`, `updated_at` | Обязательные UTC timestamps |

`refresh_tokens` (одна строка — одна активная сессия с refresh-токеном):

| Поле | Ограничение |
| --- | --- |
| `id` | UUID сессии, первичный ключ |
| `user_id` | UUID владельца, внешний ключ на `users.id` |
| `token_hash` | Уникальный SHA-256 хеш текущего refresh-токена |
| `user_agent` | Сохранённый User-Agent, ограниченный по длине перед записью |
| `created_at`, `last_used_at`, `expires_at` | Обязательные UTC timestamps |

Отозванные и истёкшие строки удаляются; отдельного `revoked_at` нет. Индексы:
`users(login)`, `refresh_tokens(token_hash)`, `refresh_tokens(user_id)` и
`refresh_tokens(expires_at)`. Уникальные индексы не дублируются обычными.

## Контракты репозиториев

`Users`: создать пользователя; получить по ID или точному логину; изменить
отображаемое имя; условно заменить хеш пароля, если прежний хеш ещё актуален.
Условная замена защищает от двух одновременных смен пароля.

`Sessions`: создать сессию; найти по хешу refresh-токена; проверить её
действительность по ID и владельцу; атомарно заменить хеш при refresh;
перечислить активные устройства владельца; отозвать одну или все остальные
сессии; удалить истёкшие записи. Ротация обновляет `last_used_at`, но не
продлевает `expires_at`. Список устройств не содержит `token_hash`.

Смена пароля с сохранением текущей сессии требует одной транзакции: условно
обновить `users.password_hash`, затем удалить остальные строки пользователя из
`refresh_tokens`. Для этой операции репозиторий предоставляет отдельный
атомарный метод, а решение вызвать его остаётся у сервиса аккаунтов.

При повторном входе с того же браузера существующая сессия переиспользуется
только если клиент прислал действующий refresh-токен того же пользователя.
Пароль при этом всё равно проверяется. После проверки парольного хеша текущий
refresh-токен ротируется, а ID сессии сохраняется. Если токен отсутствует,
истёк, отозван или относится к другому аккаунту, создаётся новая сессия.

`last_used_at` меняется при refresh, а не при каждом запросе.
Ручной отзыв сразу запрещает новые запросы от устройства, но не прерывает
уже установленный звонок.

## Проверяемые свойства первого этапа

- Повторный запуск AutoMigrate сохраняет данные.
- `Alice` и `alice` могут быть разными пользователями; два одинаковых логина
  создать нельзя.
- Ротация с одним старым хешем может успешно выполниться только один раз.
- Смена пароля удаляет все сессии, кроме текущей, в той же транзакции.
- Список устройств ограничен владельцем и не раскрывает хеш refresh-токена.
- Удалённая и истёкшая сессии не проходят проверку активности.
